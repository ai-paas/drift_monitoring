# 개발 방법론

## 1. 기본 방향

이 프로젝트는 일반적인 기능 구현 후 테스트 방식만으로 진행하지 않는다.

서버가 여러 개로 분리되어 있고, Admin Server, Drift Server, Test Feeder Server, Chart Builder, LLM Interpretation Server, UI가 API contract로 연결된다. 따라서 구현이 진행될수록 단순 unit test보다 서버 간 호출 흐름과 payload 검증이 더 중요해진다.

Codex가 코드를 수정할 때는 루트의 `CODEX_DEVELOPMENT_GUIDE.md`를 먼저 따른다. 특히 P0/P1로 등록된 함수, 자료구조, API, payload, UI state contract는 변경 전후로 반드시 확인하고, 새로 중요한 contract가 생기면 `@managed-contract` 주석과 `managed_contracts.csv` 등록을 함께 수행한다.

그래서 v1 개발은 다음 방식으로 진행한다.

```text
하네스를 확장한다.
구현을 붙인다.
하네스로 실행한다.
실패 artifact를 보고 contract와 구현을 수정한다.
다음 하네스 기능으로 넘어간다.
```

이 반복 단위를 이 문서에서는 `Harness Iteration`이라고 부른다.

## 2. Harness Iteration

하나의 Harness Iteration은 다음 순서로 진행한다.

```text
1. 이번 iteration에서 검증할 흐름을 정한다.
2. 필요한 하네스 기능을 먼저 추가한다.
3. 서버 또는 UI 구현을 추가한다.
4. 하네스로 시나리오를 실행한다.
5. runs/{run_id} artifact를 확인한다.
6. contract, payload, DB 상태, UI state 중 깨진 부분을 수정한다.
7. 통과 기준을 만족하면 다음 iteration으로 넘어간다.
```

예:

```text
Iteration 1
  하네스: Headless Mode A, health check, artifact 저장
  구현: 없음 또는 최소 연결
  검증: 서버 미기동/미구현 실패가 artifact로 남는지 확인

Iteration 2
  하네스: Admin/Drift/Test Feeder 최소 API 호출
  구현: health/reset/register endpoint
  검증: source, adapter, method, chart 등록 흐름 확인

Iteration 3
  하네스: tick/poll/timeseries 조회
  구현: feeder tick, adapter poll-once, 10분 bucket 저장
  검증: CASE-010 timeseries response 확인

Iteration 4
  하네스: drift event와 analysis payload 검증
  구현: method run, drift event, payload adapter
  검증: event marker와 analysis chart payload 확인
```

## 3. 이 방식이 특이한 이유

이 프로젝트의 하네스는 단순 테스트 보조 코드가 아니다.

하네스는 다음 역할을 동시에 가진다.

```text
서버 간 contract 검증 도구
시나리오 실행기
logical time controller
API call recorder
payload snapshot 저장소
failure artifact 수집기
향후 PyQt6 관제 UI의 backend core
```

따라서 하네스는 구현이 끝난 뒤에 붙이는 테스트가 아니라, 구현과 함께 성장해야 한다.

## 4. 원칙

```text
하네스는 먼저 headless로 동작해야 한다.
PyQt6 UI에는 테스트 로직을 넣지 않는다.
하네스 실행 결과는 항상 runs/{run_id}에 남긴다.
contract 기준은 api_contracts.md다.
서버가 미구현이면 테스트를 성공 처리하지 않고 실패 artifact를 남긴다.
하네스가 실제 운영 동작을 바꾸면 안 된다.
Mode A는 항상 유지한다.
Mode B-D는 contract 관찰, stub, fault injection을 위해 추가한다.
```

## 5. 완료 판단

각 iteration은 다음 산출물이 있어야 완료된 것으로 본다.

```text
하네스 시나리오 또는 하네스 기능
관련 서버/UI 구현
실행된 run artifact
validation_report.json
summary.md
필요 시 문서 보강
```

구현이 부분적으로만 되어 있더라도, 하네스가 어디까지 통과했고 어디서 실패했는지를 명확히 남기면 다음 iteration의 출발점으로 사용할 수 있다.
