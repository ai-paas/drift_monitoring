# Drift Chart Explanation Authoring Guide

이 문서는 drift chart 설명을 작성할 때 지켜야 할 기준이다. 갤러리의 설명은 사용자가 차트 이미지를 보면서 "이 패널이 무엇을 말하는지", "현재 예시 데이터에서는 어떤 일이 일어났는지", "어떤 결론까지 말할 수 있는지"를 바로 이해할 수 있어야 한다.

## 1. 목적

차트 설명은 chart id의 기능 요약이 아니라 실제 화면 해석이어야 한다.

나쁜 설명:

```text
Detector State Timeline: normal, warning, alternate, replace
```

좋은 설명:

```text
Detector State Timeline: t=1~10은 normal 상태로 유지되다가 t=11부터 warning으로 바뀐다.
t=14부터 alternate tree 상태가 시작되고, t=23에서 replace marker가 나타난다.
이 순서는 detector가 먼저 이상 징후를 감지했고, 이후 대체 tree를 충분히 키운 뒤 교체했다는 뜻이다.
```

## 2. 설명 단위

각 chart 설명은 아래 다섯 단위를 모두 포함한다.

1. 현재 상황을 사람이 이해할 수 있는 말로 요약한 문단
2. 전체 차트가 답하는 질문
3. 패널별 화면 요소와 예시 데이터의 움직임
4. 패널들을 함께 읽었을 때의 drift 또는 대응 판단
5. 말하면 안 되는 과잉 해석과 추가 확인 항목

## 2.1 현재 상황 요약

각 chart 설명은 패널별 해석 전에 "현재 어떤 상황인가"를 먼저 설명해야 한다. 사용자가 도메인 지식 없이도 차트의 사건 흐름을 이해할 수 있도록, 모델/데이터/감지/대응/결론을 한 문단으로 연결한다.

권장 형식:

```text
운영 중인 HAT 모델의 online accuracy가 안정 구간 이후 떨어지기 시작했다.
detector는 t=11부터 warning을 내고, HAT는 t=14부터 alternate tree를 키운다.
t=23에서 replacement가 발생한 뒤 accuracy가 회복되므로,
이 예시는 HAT가 drift 후보 구간에 구조적으로 적응한 상황이다.
```

이 요약은 패널별 수치 나열을 대체하지 않는다. 먼저 전체 상황을 설명하고, 그 다음 각 패널에서 그 판단을 뒷받침하는 값을 확인한다.

## 3. 패널별 설명 규칙

각 패널 설명은 다음 순서로 쓴다.

```text
패널 이름
  1. 이 패널에서 보는 데이터와 축
  2. 이 예시에서 실제로 보이는 패턴
  3. 그 패턴이 의미하는 운영/통계적 해석
  4. 다른 패널과 연결해서 확인할 점
```

단순히 구성요소 이름만 나열하지 않는다. `trend`, `timeline`, `matrix`, `scatter`, `heatmap` 같은 시각 요소는 사용자가 읽어야 할 값, 구간, 방향, 순서를 함께 설명해야 한다.

## 4. 데이터 기반 설명 규칙

차트 코드에 고정 예시 데이터가 있으면 설명에 주요 수치를 넣는다.

- time index, window index, threshold index
- min/max, gap, p-value, score, threshold
- 상태 전환 시점
- marker가 찍힌 이벤트 시점
- 어떤 series가 증가/감소/회복/분리되는지

수치가 화면에 보이는 경우 보고서 문장에서도 같은 수치를 사용한다. 수치가 예시 데이터일 때는 "이 예시에서는"이라고 명시한다.

## 5. 해석 연결 규칙

패널을 따로 설명한 뒤 반드시 "그래서 무엇을 뜻하는가"를 연결한다.

예:

```text
accuracy 하락만으로 HAT가 drift에 대응했다고 말하지 않는다.
warning -> alternate -> replace timeline과 alternate tree size 증가가 함께 나타나야
HAT가 drift 후보에 대해 구조적으로 적응했다고 해석할 수 있다.
```

## 6. 금지 문장

다음 형태의 설명은 피한다.

- chart id나 variant 용도를 반복하는 문장
- 패널 이름만 번역한 문장
- "확인한다", "보여준다"로 끝나고 실제 패턴을 말하지 않는 문장
- p-value, threshold, alarm, marker만 보고 원인을 단정하는 문장
- 예시 데이터인지 실제 운영 데이터인지 구분하지 않는 문장

## 7. 최소 품질 기준

차트 하나의 설명은 최소한 다음 질문에 답해야 한다.

```text
1. 왼쪽 큰 패널에서 사용자는 무엇을 먼저 봐야 하는가?
2. 우측 상단 패널에서 어떤 상태/분포/판단이 바뀌는가?
3. 우측 하단 패널은 첫 두 패널의 결론을 어떻게 보강하거나 반박하는가?
4. 이 예시에서는 drift 후보, 적응 후보, 또는 추가 확인 후보 중 무엇인가?
5. 이 차트만 보고 단정하면 안 되는 것은 무엇인가?
```

## 8. 갤러리 표시 문구 작성 규칙

`charts/chart_*.html`의 panel 설명은 갤러리의 `차트 화면 읽기`에 직접 표시된다. 따라서 한 줄이라도 실제 화면 해석을 담아야 한다.

권장 형식:

```text
패널 제목: t=11 warning, t=14 alternate, t=23 replace처럼 상태 전환 순서를 읽는다.
```

피해야 할 형식:

```text
패널 제목: normal, warning, alternate, replace
```

## 9. 수정 순서

차트 설명을 고칠 때는 다음 순서로 진행한다.

1. 해당 chart HTML/JS에서 화면 구성과 예시 데이터를 확인한다.
2. chart interpretation 문서의 목적, 구성, 해석 순서, 예시 해석을 보강한다.
3. chart HTML의 panel 설명과 notes 문구를 보강한다.
4. 갤러리에서 `차트 화면 읽기`가 사람이 이해할 수 있는 문장으로 보이는지 확인한다.
5. 필요한 경우 DB import를 재생성/재적재한다.
