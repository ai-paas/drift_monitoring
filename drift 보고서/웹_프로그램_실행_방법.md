# 웹 프로그램 실행 방법

## 권장 실행 방법

이 폴더의 웹 프로그램은 FastAPI 기반 차트 갤러리 서버다. 현재 갤러리의 차트 목록, 설명, 탐지 방법 연결은 Markdown/CSV 파일이 아니라 PostgreSQL의 `drift_monitoring` DB에서 읽는다.

따라서 먼저 Docker Desktop의 PostgreSQL 컨테이너가 실행 중이고 DB import가 완료되어 있어야 한다.

## DB 준비 확인

PostgreSQL 컨테이너 확인:

```powershell
docker ps --filter "name=lci-postgres"
```

DB count 확인:

```powershell
docker exec lci-postgres psql -U postgres -d drift_monitoring -c "select count(*) from chart_definition;"
```

정상이라면 현재 기준으로 `53`이 나온다.

DB를 다시 만들거나 최신 Markdown/CSV 내용을 재적재하려면:

```powershell
python db\import_drift_db.py
docker cp db\schema.sql lci-postgres:/tmp/drift_schema.sql
docker exec lci-postgres psql -U postgres -d drift_monitoring -v ON_ERROR_STOP=1 -f /tmp/drift_schema.sql
docker cp db\load_data.sql lci-postgres:/tmp/drift_load_data.sql
docker exec lci-postgres psql -U postgres -d drift_monitoring -v ON_ERROR_STOP=1 -q -f /tmp/drift_load_data.sql
```

서버의 기본 DB 연결값은 다음과 같다.

```text
DRIFT_DB_HOST=127.0.0.1
DRIFT_DB_PORT=5432
DRIFT_DB_NAME=drift_monitoring
DRIFT_DB_USER=postgres
DRIFT_DB_PASSWORD=postgres
```

다른 PostgreSQL을 쓰려면 위 환경변수를 설정한 뒤 서버를 실행한다.

## 서버 실행

가장 안정적인 실행 방법은 `run_chart_server.cmd`를 실행하는 것이다.

현재 `run_chart_server.cmd`는 배치 파일 자신의 위치(`%~dp0`)로 이동한 뒤 서버를 실행한다. 따라서 한글 폴더명(`drift 보고서`)을 하드코딩하지 않고, 경로 인코딩 깨짐 문제를 피한다.

PowerShell에서 실행:

```powershell
cd "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 보고서"
.\run_chart_server.cmd
```

정상 실행되면 콘솔 창에 다음 문구가 보인다.

```text
Drift chart selector server: http://127.0.0.1:8765/gallery.html
Press Ctrl+C to stop.
INFO:     Uvicorn running on http://127.0.0.1:8765
```

이 콘솔 창은 닫지 않는다. 창을 닫으면 웹 서버도 종료된다.

`run_chart_server.cmd`의 핵심 내용은 아래처럼 상대 실행 위치를 쓰는 형태여야 한다.

```bat
cd /d "%~dp0"
```

파일 안에 `drift 蹂닿퀬??`처럼 깨진 한글 경로가 남아 있으면 현재 버전으로 다시 고치거나 아래 직접 실행 명령을 사용한다.

## 서버가 안 뜰 때 확인할 것

### 1. 서버 창이 열려 있는지 확인

서버를 실행한 콘솔 창이 열려 있어야 한다. 창을 닫으면 서버도 종료된다.

콘솔에서 직접 실행했을 때 아래와 같은 문구가 보이면 서버는 정상으로 뜬 것이다.

```text
INFO:     Uvicorn running on http://127.0.0.1:8765
```

### 2. 포트가 이미 사용 중인지 확인

```powershell
Get-NetTCPConnection -LocalPort 8765 -ErrorAction SilentlyContinue |
  Select-Object LocalAddress,LocalPort,State,OwningProcess
```

결과가 나오고 서버가 접속되지 않으면 기존 프로세스가 포트를 점유한 상태일 수 있다. 이 경우 `OwningProcess` 값을 확인한 뒤 종료한다.

```powershell
Stop-Process -Id <OwningProcess>
```

그 다음 서버를 다시 실행한다.

### 3. 배치 파일의 한글 경로 깨짐 확인

`run_chart_server.cmd`를 실행했는데 창이 바로 닫히거나 아무 포트도 열리지 않으면 파일 안의 경로가 깨졌는지 확인한다.

문제가 있는 예:

```bat
cd /d "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 蹂닿퀬??
```

위처럼 한글 경로가 깨지고 닫는 따옴표도 사라진 상태면 `cmd`가 작업 폴더로 이동하지 못한다.

정상 예:

```bat
cd /d "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 보고서"
```

경로가 깨져 있으면 `cd`가 실패하므로 서버가 시작되지 않는다. 이 경우 배치 파일을 고치거나 아래 직접 실행 명령을 사용한다.

```powershell
cd "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 보고서"
"C:\Users\jklee\anaconda3\envs\qt_env\python.exe" -u "charts\chart_selector_server.py"
```

### 4. Python 경로 확인

`run_chart_server.cmd`는 아래 Python을 사용한다.

```text
C:\Users\jklee\anaconda3\envs\qt_env\python.exe
```

이 파일이 없거나 환경이 바뀌면 `run_chart_server.cmd`의 Python 경로를 수정해야 한다.

### 5. Codex 또는 자동화 환경의 백그라운드 실행 제한 확인

Codex 같은 샌드박스 실행 환경에서는 `Start-Process`, `cmd start`, `Start-Job`, `pythonw` 방식으로 띄운 장기 실행 서버가 바로 종료되거나 포트를 열지 못할 수 있다.

이 경우 DB나 FastAPI 문제가 아니라 실행 환경의 프로세스 유지 제한일 수 있다. 같은 명령을 전면 콘솔에서 실행했을 때 서버가 뜨면 애플리케이션 자체는 정상이다.

샌드박스 환경에서 실행해야 한다면 샌드박스 밖 실행 승인을 받은 뒤 서버 콘솔을 시작한다.

## 직접 실행 방법

배치 파일 없이 직접 실행하려면 다음 명령을 사용한다.

```powershell
cd "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 보고서"
"C:\Users\jklee\anaconda3\envs\qt_env\python.exe" -u "charts\chart_selector_server.py"
```

이 명령도 콘솔 창을 닫으면 서버가 종료된다.

FastAPI 앱 객체를 직접 uvicorn으로 실행할 수도 있다.

```powershell
cd "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 보고서"
python -m uvicorn charts.chart_selector_server:app --host 127.0.0.1 --port 8765
```

## 주의: 숨김 백그라운드 실행

아래와 같은 `Start-Process ... -WindowStyle Hidden` 방식은 Codex 샌드박스 같은 자동화 환경에서 프로세스가 바로 종료되거나 포트를 열지 못하는 경우가 있었다.

```powershell
Start-Process -FilePath "C:\Users\jklee\anaconda3\envs\qt_env\python.exe" `
  -ArgumentList @("-u", "charts\chart_selector_server.py") `
  -WorkingDirectory "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 보고서" `
  -WindowStyle Hidden
```

따라서 기본 실행은 보이는 PowerShell 콘솔에서 `run_chart_server.cmd`를 실행하는 방식을 사용한다.

## 문서 데이터 재생성

차트 해석 문서나 algorithm variant 문서를 수정한 뒤에는 DB import 데이터를 다시 생성하고 적재한다.

```powershell
cd "C:\Users\jklee\PycharmProjects\drift_llm_intepretation\drift 보고서"
python db\import_drift_db.py
docker cp db\load_data.sql lci-postgres:/tmp/drift_load_data.sql
docker exec lci-postgres psql -U postgres -d drift_monitoring -v ON_ERROR_STOP=1 -q -f /tmp/drift_load_data.sql
```

기존의 아래 생성 파일은 더 이상 갤러리 UI의 기준 데이터가 아니다.

```text
charts\descriptions\*_desc.html
charts\description_data.js
charts\method_data.js
charts\method_description_data.js
```

차트 관련 원천 문서는 `chart_docs/`에 있고, 원천 문서 연결 기준은 `문서_웹_연결_정리.md`를 따른다. 웹 UI는 `/api/gallery-data`를 통해 PostgreSQL 데이터를 읽는다.

## 종료 방법

가장 쉬운 방법은 서버를 직접 실행한 콘솔 창에서 `Ctrl+C`를 누르는 것이다.

콘솔 창을 찾기 어렵다면 포트 점유 프로세스를 찾아 종료한다.

```powershell
Get-NetTCPConnection -LocalPort 8765 -ErrorAction SilentlyContinue |
  Select-Object LocalAddress,LocalPort,State,OwningProcess
```

```powershell
Stop-Process -Id <OwningProcess>
```
